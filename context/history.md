# History

- Scaffold (**Oct 5, 2026**) - setup project initially
- Home Page (**Oct 5, 2026**) - build home page `/` from the mockup
  - Shared navbar (logo, nav links, light/dark toggle, menu on phones)
  - Hero with rice field background, ARIMAX description, page search bar, Get Started card, and AniMo mascot
  - Non-home nav links and Get Started use `#` placeholders until their pages exist
- Database Schema Design (**Oct 6, 2026**) - document the Prisma schema in `context/database-schema.md`
  - Auth: next-auth Credentials provider with JWT sessions, `bcryptjs` password hashes, `tokenVersion` to force logout
  - AWS-IAM-style RBAC: roles, policies and statements (allow/deny, actions, resources), with seeded Admin, Analyst and Viewer roles
  - Domain: multiple rice fields, historical yield records, ARIMAX model configurations, per-field evaluations (MAE, RMSE, MAPE) and predictions
  - ARIMAX uses the `arima` npm package; it was tested on sample data and models are refitted on each prediction
  - Audit log filled by Postgres triggers on the important tables
  - Login rate limiting stored in Postgres (`LoginAttempt`): 5 failed attempts per email or IP in 15 minutes, no Redis
- Setup Prisma (**Oct 6, 2026**) - Prisma 7 + PostgreSQL with the full schema from `context/database-schema.md`
  - `prisma.config.ts` holds the datasource URL and seed command; `.env` holds only `DATABASE_URL`
  - `prisma-client` generator outputs to `src/generated/prisma` (gitignored, regenerated on `postinstall`); `prisma` pinned to 7.10 because npm `latest` points to an 8.0 RC
  - Migrations: `init` (all tables) and `audit_triggers` (raw SQL trigger writing `AuditLog` for 9 tables, strips `passwordHash`, reads `app.user_id`)
  - `src/lib/prisma.ts`: `server-only` Prisma Client singleton using `@prisma/adapter-pg`
  - `prisma/seed.ts`: re-runnable seed of system policies, roles (Admin, Analyst, Viewer) and the `admin@animo.local` admin user
  - `db:*` npm scripts for generate, migrate, deploy, status, seed and studio
- Lowercase Plural Table Names (**Oct 11, 2026**) - map every Prisma model to a lowercase, plural, snake_case table with `@@map`
  - `User` → `users`, `LoginAttempt` → `login_attempts`, `UserRole` → `user_roles`, `AuditLog` → `audit_logs`, etc.; model names and columns unchanged
  - Deleted and recreated the `init` and `audit_triggers` migrations; trigger SQL now uses the new table names, so `audit_logs.tableName` stores e.g. `users`
  - Updated `context/database-schema.md` (overview, diagram, schema block, audit log, conventions)
  - Existing local databases need `prisma migrate reset` and `npm run db:generate`
- Auth Setup and Login Page (**Oct 11, 2026**) - email + password login with `next-auth@4.24.15` (Credentials provider, JWT sessions, no adapter)
  - `/login` page: rice field image on the left 3/4 with opacity and left/bottom fades, form on the right; image hidden on small screens; no sign-up or forgot password
  - `authorize()` validates with Zod, rate limits 5 failed attempts per email or IP in 15 minutes, records every attempt in `login_attempts`, compares unknown emails against a dummy hash, and updates `lastLoginAt` with the user set as the audit actor
  - JWT and session carry only `userId` and `tokenVersion`; `getCurrentUser()` (`server-only`, React `cache()`) rejects inactive users and stale `tokenVersion`
  - `src/proxy.ts` uses `withAuth` as an optimistic check; `/` and `/login` re-check with `getCurrentUser()`
  - Chakra toaster (bottom-right) for login errors; `NEXTAUTH_SECRET` and `NEXTAUTH_URL` added to `.env.example`
