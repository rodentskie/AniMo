# History

- Scaffold (**Oct 5, 2026**) - setup project initially
- Home Page (**Oct 5, 2026**) - build home page `/` from the mockup
  - Shared navbar (logo, nav links, light/dark toggle, menu on phones)
  - Hero with rice field background, ARIMAX description, page search bar, Get Started card, and AniMo mascot
  - Non-home nav links and Get Started use `#` placeholders until their pages exist
- Database Schema Design (**Oct 6, 2026**) - document the Prisma schema in `context/database-schema.md`
  - Auth: next-auth Credentials provider with JWT sessions, `bcryptjs` password hashes, `tokenVersion` to force logout
  - AWS-IAM-style RBAC: roles, policies and statements (allow/deny, actions, resources), with seeded Admin, Analyst and Viewer roles
  - Domain: multiple rice fields, historical yield records, ARIMAX model configurations, per-field evaluations (MAE, RMSE, MAPE) and predictions
  - ARIMAX uses the `arima` npm package; it was tested on sample data and models are refitted on each prediction
  - Audit log filled by Postgres triggers on the important tables
  - Login rate limiting stored in Postgres (`LoginAttempt`): 5 failed attempts per email or IP in 15 minutes, no Redis
- Setup Prisma (**Oct 6, 2026**) - Prisma 7 + PostgreSQL with the full schema from `context/database-schema.md`
  - `prisma.config.ts` holds the datasource URL and seed command; `.env` holds only `DATABASE_URL`
  - `prisma-client` generator outputs to `src/generated/prisma` (gitignored, regenerated on `postinstall`); `prisma` pinned to 7.10 because npm `latest` points to an 8.0 RC
  - Migrations: `init` (all tables) and `audit_triggers` (raw SQL trigger writing `AuditLog` for 9 tables, strips `passwordHash`, reads `app.user_id`)
  - `src/lib/prisma.ts`: `server-only` Prisma Client singleton using `@prisma/adapter-pg`
  - `prisma/seed.ts`: re-runnable seed of system policies, roles (Admin, Analyst, Viewer) and the `admin@animo.local` admin user
  - `db:*` npm scripts for generate, migrate, deploy, status, seed and studio
- Lowercase Plural Table Names (**Oct 11, 2026**) - map every Prisma model to a lowercase, plural, snake_case table with `@@map`
  - `User` → `users`, `LoginAttempt` → `login_attempts`, `UserRole` → `user_roles`, `AuditLog` → `audit_logs`, etc.; model names and columns unchanged
  - Deleted and recreated the `init` and `audit_triggers` migrations; trigger SQL now uses the new table names, so `audit_logs.tableName` stores e.g. `users`
  - Updated `context/database-schema.md` (overview, diagram, schema block, audit log, conventions)
  - Existing local databases need `prisma migrate reset` and `npm run db:generate`
- Auth Setup and Login Page (**Oct 11, 2026**) - email + password login with `next-auth@4.24.15` (Credentials provider, JWT sessions, no adapter)
  - `/login` page: rice field image on the left 3/4 with opacity and left/bottom fades, form on the right; image hidden on small screens; no sign-up or forgot password
  - `authorize()` validates with Zod, rate limits 5 failed attempts per email or IP in 15 minutes, records every attempt in `login_attempts`, compares unknown emails against a dummy hash, and updates `lastLoginAt` with the user set as the audit actor
  - JWT and session carry only `userId` and `tokenVersion`; `getCurrentUser()` (`server-only`, React `cache()`) rejects inactive users and stale `tokenVersion`
  - `src/proxy.ts` uses `withAuth` as an optimistic check; `/` and `/login` re-check with `getCurrentUser()`
  - Chakra toaster (bottom-right) for login errors; `NEXTAUTH_SECRET` and `NEXTAUTH_URL` added to `.env.example`
- Prisma ARIMA Update (**Nov 27, 2026**) - move the database from the ARIMAX design to ARIMA (yearly rice production per location and irrigation status)
  - Removed `Season`, `Field`, `YieldRecord`, `ArimaxModel`; added `IrrigationStatus`, `ProductionOutlook`, `Location`, `ProductionRecord`, `ArimaModel`, `PredictionPoint`, `Feedback`
  - `ModelEvaluation` now uses `locationId` + `irrigation` and years; `Prediction` is a forecast run (`horizon`, `historicalAvg`, `outlook`) with yearly `PredictionPoint`s; `User` has a `feedback` relation
  - `arima_domain` migration drops the old tables (their triggers go with them) and adds audit triggers on `locations`, `production_records`, `arima_models`; no triggers on predictions, prediction points, evaluations or feedback
  - Seed: `field:*` → `location:*`, Analyst and Viewer get `feedback:Read` and `feedback:Submit`
  - Replaced ARIMAX wording in the layout metadata and home hero
- IAM Authorization (**Nov 27, 2026**) - load each user's permissions and check them on the server
  - `src/lib/iam.ts` (`server-only`): `matches()` (`*` wildcard, whole-string, other regex characters escaped), `isAllowed()` (explicit `DENY` wins, then `ALLOW`, otherwise implicit deny), `resourceArn()` and `defaultResource()` (`dataset:Create` → `animo:dataset/*`)
  - `getCurrentUser()` loads roles → policies → statements and returns `roleNames` and flattened `statements`; still `cache()`d with the `isActive` / `tokenVersion` checks
  - Prisma `relationJoins` preview feature enabled so the nested lookup is one SQL query (was 6); `join` is now the default relation strategy app-wide
  - `src/lib/guards.ts`: `requirePermission()` (redirect to `/login` or `forbidden()`), `authorize()` for Server Actions, `can()` for hiding UI, and `PERMISSION_DENIED_ERROR`
  - `experimental.authInterrupts` enabled; `src/app/forbidden.tsx` shows a friendly "no access" page with a link home
  - Types in `src/types/iam.ts`: `Statement`, `CurrentUser`
- Audited Write Helper (**Nov 27, 2026**) - helper so audit triggers record who made each change
  - `src/lib/audit.ts` (`server-only`): `withAuditUser(userId, fn)` runs an interactive `prisma.$transaction`, first `SELECT set_config('app.user_id', ${userId}, true)` (parameterised, transaction-local so it never leaks to pooled connections), then `fn(tx)`
  - `authorize()` now updates `lastLoginAt` through `withAuditUser` (same behaviour, replaces the manual batch transaction)
  - Rule: every application write to an audited table must go through `withAuditUser`
- App Navigation (**Nov 27, 2026**) - navbar links, user menu with logout, and placeholder pages
  - `src/lib/nav.ts`: six routes with `react-icons/lu` icons; top bar shows Home, Data, Prediction, Evaluation; Definition of Terms and Settings live in the user menu; phone menu lists all six
  - `isActivePath()` sets `aria-current` on exact and child routes (e.g. `/settings/users` → Settings)
  - `UserMenu`: avatar button next to the color mode toggle, shows full name and role names, links to Terms and Settings, and Log out via `signOut({ callbackUrl: "/login" })`
  - `AppShell` (Navbar + main) receives the user from each page's `getCurrentUser()`; no shared layout so `/login` stays without a navbar
  - Placeholder pages `/data`, `/prediction`, `/evaluation`, `/terms`, `/settings` (heading only, redirect to `/login` when logged out); home "Get Started" → `/data`
- Locations Management (**Nov 27, 2026**) - Admins and Analysts manage the locations that production data is recorded for
  - `/settings/locations` (`requirePermission("location:Read")`): table of Province, Municipality, Barangay, Status, record count and row actions; "Locations" card on `/settings` shown with `location:Read`
  - Buttons depend on permissions: Add (`location:Create`), Edit and Activate / Deactivate (`location:Update`), Delete (`location:Delete`, hidden when the location has production records, predictions or evaluations); Viewers see the list only
  - `src/actions/locations.ts`: `createLocation`, `updateLocation`, `setLocationActive`, `deleteLocation` (authorize → Zod → `withAuditUser` → `revalidatePath` → `{ success, data, error }`)
  - Duplicates are checked in the transaction (ignoring case) because Postgres treats `NULL`s as distinct in the unique index; `P2002` also maps to "This location already exists"
  - Delete re-checks history on the server and returns "This location has data. Deactivate it instead."
  - `src/types/location.ts`: Zod schema (province 1–100, municipality / barangay max 100, empty → `null`), `LocationRow`, `ActionResult<T>`; `src/lib/location.ts`: `formatLocation()` → "Barangay, Municipality, Province"
  - Chakra `Dialog` for add / edit, and an `alertdialog` delete confirmation that enables the Delete button only after typing "delete"
  - Settings card renders the icon as a child of `Icon` (passing `as={LuMapPin}` from a server component fails at runtime)
